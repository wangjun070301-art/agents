# 流水线控制台 · 使用说明

一套本地运行的多 Agent 流水线平台。界面上能配置项目、跑任务、
看实时输出、推进阶段、人工放行阻塞。所有操作都留痕，重启不丢。

---

## 一、启动

```powershell
cd C:\Users\13420\Documents\ChatGPT\agents
npm ci
npm run build
node tools/panel.mjs
```

打开浏览器访问：

```
http://127.0.0.1:18493
```

**参数**：

| 参数 | 默认 | 作用 |
|---|---|---|
| `--state DIR` | `workflow-state/` | 状态存哪（流水线进度、任务记录、配置） |
| `--port N` | `18493` | 端口 |

例：

```powershell
node tools/panel.mjs --state D:\my-project-state --port 19000
```

## 二、第一次使用（3 步）

**1. 填项目配置（左下角）**

- 名称：随便起，比如 `fixture`
- 代码目录：项目绝对路径（必须存在，不存在会报错）
- 模型：默认 `deepseek-v4.1-flash-solo`，按你的代理改
- 沙箱：默认 `bypass`（这台机器上子进程必须 bypass 才能执行命令）

**2. 加需求**

点"+ 加一条需求"，填：
- 需求编号：`REQ-1`
- 描述：这条需求要解决什么

再点"+ 加验收项"，填：
- 验收编号：`AC-1`
- 描述：怎么算通过
- 类型：`automated`（命令检查）或 `manual`（人工确认）
- 命令：automated 类型必填，例如 `node --test`

**3. 加任务 + 保存**

点"+ 加一个任务"，填：

| 字段 | 说明 |
|---|---|
| 任务编号 | `T-1` |
| 角色 | developer / tester / reviewer |
| 目标 | 要做什么 |
| 可写目录 | 逗号分隔，如 `src, test` |
| 交付物 | 逗号分隔，如 `src/a.js` |
| 验收编号 | 逗号分隔，如 `AC-1` |
| 依赖任务 | 逗号分隔，如 `T-0`（有依赖才填） |

点"保存配置"。右上角出现项目名即成功。

## 三、跑任务

**单个任务**：任务列表里点"运行这个任务"。

**整个计划**：点"跑整个计划（按依赖顺序）"。依赖关系会自动排序，
先跑没依赖的，再跑有依赖的；某个任务失败，依赖它的任务会被跳过。

跑的时候：
- 右上角显示"运行中"
- 任务列表下方出现"实时输出"框，能看到模型在干什么
- 想停就点"取消当前任务"

## 四、阶段与门禁

流水线有 13 个阶段：接单 → 澄清 → 基线 → 需求规格 → 计划 → 派工 →
实现 → 审查 → 验证 → 集成 → 验收 → 交付 → 归档。

**推进**：左上角"可推进到"列出当前能去的阶段。带 `(G2)` 这类标记的
按钮是灰的——那是门禁，需要任务产出证据才能过，不能靠点按钮。

**被门禁拦住**：跑完任务后，如果门禁不通过，阶段不会前进，历史里会
记录拦截原因（例如"验证命令没跑""声明了测试但输出里没有"）。

**人工放行**：阶段变成"已阻塞"时，出现放行输入框：
- 填"放行回哪个阶段"（默认填了来源阶段）
- 填"为什么可以继续"（会记入历史）
- 点"放行"

只有可重试故障（比如子进程被杀）耗尽力竭才会自动阻塞；
超时和取消不会冻结流水线。

## 五、历史与记录

**阶段历史**：每次阶段变化都记一笔——从哪到哪、几点、为什么、门禁结果。
上面有筛选框，输入阶段名（如"实现"）或门禁号（如 `G2`）实时过滤。

**任务记录**：页面底部列每个任务的尝试和失败原因。

## 六、导入导出配置

项目配置区有"导出 JSON"和"导入 JSON"：
- 导出：把当前配置存成文件，方便备份或复制到别的机器
- 导入：选文件自动填回表单，检查后点保存

## 七、常见问题

**Q：点保存报"repo_path does not exist"**
代码目录填错了或不存在。填存在的绝对路径。

**Q：跑任务按钮是灰的**
没有保存配置，或者已有任务在跑（同一时间只允许一个）。

**Q：阶段按钮是灰的还带 (G2)**
那是门禁。先跑一个能产出该门禁证据的任务，别硬点。

**Q：任务一直失败，报"output contains no test result"**
子进程跑了命令但输出里没有测试结果。检查验收项的命令是否真的会输出
测试格式（如 `node --test`），别用只会打印 `ok` 的普通脚本。

**Q：取消点了没反应**
取消是请求式——告诉子进程停。如果子进程在等待网络响应，可能要等一会。

**Q：重启电脑后配置还在吗**
在。状态存在 `workflow-state/` 目录（或你 `--state` 指定的目录），
重启后重新 `node tools/panel.mjs` 就能接上。

## 八、数据存哪

```
workflow-state/
  pipeline.json       流水线阶段 + 历史
  project.json        项目配置
  tasks/<task-id>/    每个任务的尝试记录和失败原因
  codex-home/         子进程用的 CODEX_HOME（含 auth 副本）
```

这些目录已被 `.gitignore` 排除，不会提交到仓库。

## 九、限制

1. 同一时间只能跑一个任务（防撞车）
2. 界面只能放行阻塞，不能手动改阶段为任意值（有门禁的边必须靠证据）
3. 沙箱默认 `bypass`——子进程需要完全权限才能执行命令，这是这台机器的硬约束
4. 界面绑在 `127.0.0.1`，只有本机能访问，没有认证（本机单用户场景够用）
