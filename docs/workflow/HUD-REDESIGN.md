# Cyber-HUD：控制台重做

## 为什么重做

P16–P20 的面板是逐轮加出来的：先有状态页，再塞表单，再塞输出框。
功能都在，但信息层次是平的——阶段、配置、任务、历史四件事
挤在同一列里，跑起来时看不出哪一块在动。

## 新的结构

三列，每列一个职责：

| 列 | 内容 |
|---|---|
| 左 | **Agent Matrix**（阶段地图 + 六道门禁状态）· **Intervention**（可推进阶段、放行、强制阻塞） |
| 中 | **Direct Control**（项目配置表单）· **Task Queue**（任务卡片 + 执行整个工作流）· **Live Terminal**（实时输出 + 中断） |
| 右 | **History**（时间线 + 筛选）· **Run Records**（每次尝试与失败原因） |

阶段地图把 13 个阶段画成纵向流程：已过、当前、阻塞三种状态各自有
颜色和标记。门禁是六个独立徽章，通过的打勾并亮起——一眼能看出
卡在哪一道。

## 视觉

深色底、青色主色、等宽字体、细网格背景。不是装饰：这是一个需要
长时间盯着看的界面，等宽字体让日志和路径对齐。

状态用三种颜色说话：

| 颜色 | 含义 |
|---|---|
| 青 | 当前 / 可操作 |
| 橙 | 等待人工（阻塞、取消中） |
| 红 | 失败 |

## 密钥脱敏

`redactSecrets()` 在输出进面板之前跑一遍：

```ts
/\b(gho|ghp|ghs|github_pat)_[A-Za-z0-9_]+/g   → ***
/\bBearer\s+[A-Za-z0-9._~+/=-]{8,}/gi          → Bearer ***
/\b(sk|pk|rk)-[A-Za-z0-9]{20,}/g               → $1-***
/\b(api[_-]?key|token|secret)\s*[=:]\s*.../gi  → $1=***
```

子进程的日志里可能有粘贴进来的 token。面板是长期开着的窗口，
不该成为泄露渠道。

**这是模式匹配，不是密钥扫描器**：认不出的格式不会被打码。

## 桌面壳

`app/main.cjs` 用 Electron 起同一个面板服务（端口 0，随机分配），
然后开一个原生窗口指过去。关窗即停服务。

```powershell
npm run app        # 直接开
npm run app:build  # 先编译再开
```

`PANEL_STATE` 环境变量可以指向别的状态目录。
