# P18：表单配置与整份计划

## 这一轮补什么

P17 要求手写 `project.json`。一份真实配置里有需求、验收项、任务信封，
手写等于给自己埋格式错误。

## 做了什么

**表单**：需求 → 验收项 → 任务，三层可以增删。表单自己持有一份模型，
只在页面首次加载时从服务端填一次——否则 3 秒一次的状态刷新会把
正在输入的内容冲掉。

**整份计划**：新增 `POST /api/run-plan`，按依赖顺序跑完所有任务。

## 表单不替你补的东西

保存时前端只补真正无法从表单得到的字段：

| 字段 | 补什么 | 为什么 |
|---|---|---|
| `repo_path` | 顶层配置的目录 | 每个任务都要，但只该填一次 |
| `base_revision` | `init` | 表单没有这一项 |
| `deliverables` | 空则 `(none)` | 协议允许"不改文件"的任务 |
| `manual_check` | `owner: He`, `procedure: 人工确认` | 人工验收项必须有具名负责人 |

**`(none)` 不是占位符**，是协议里的显式"这个任务不产出文件"。
门禁认得它，不会去找一个叫 `(none)` 的文件。

## 测试（新增 1 项）

内联脚本藏在 `.ts` 的模板字符串里，TypeScript 编译器看不见它。
一个漏掉的括号只会在浏览器里炸。所以测试把 `<script>` 抠出来，
用 `node --check` 过一遍语法。

| 检查 | 结果 |
|---|---|
| 面板内联脚本语法合法 | 通过 |
