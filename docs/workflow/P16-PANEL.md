# P16：流水线控制台

## 这一轮补什么

P15 之前，看阶段只能读 `pipeline.json`，放行只能写脚本调 `advance`。
协议是完整的，人却没有入口。

## 做了什么

一个本地 HTTP 服务，绑 `127.0.0.1`，没有认证（唯一能访问的是本机）。

| 路由 | 作用 |
|---|---|
| `GET /` | 单页控制台 |
| `GET /api/state` | 阶段、阻塞态、已过门禁、历史、任务记录 |
| `POST /api/release` | 从 BLOCKED 放行，必须同时给 `to` 和 `from` |
| `POST /api/block` | 人工阻塞，备注进历史 |

## 三个设计决定

**1. 放行必须点名原阶段。**
BLOCKED 不是"去某个地方"，是"回到来的地方"。只给 `to` 不给 `from`
的请求被拒绝，否则 BLOCKED 就成了任意跳转的入口。

**2. 备注是人的原话，不是占位符。**
放行时填的 `note` 直接进历史。历史里出现"某个人点了按钮"没有价值。

**3. 阶段持久化到 `stateDir/pipeline.json`。**
`Pipeline.restore()` 在文件缺失或损坏时回到 INTAKE，而不是拒绝启动——
状态文件坏了不该让整个控制台打不开。
