# P20：配置导入导出与历史筛选

## 这一轮补什么

两份配置在两台机器之间搬，只能靠复制 `project.json`；
历史一长，找"哪一步被 G2 拦了"只能肉眼扫。

## 导出

前端把当前表单拼成一份 JSON 下载：

```json
{
  "name": "...",
  "repo_path": "...",
  "model": "...",
  "sandbox": "...",
  "requirements": [...],
  "tasks": [...]
}
```

导的是**表单里的当前值**，不是服务端已保存的值。改完没保存也能先导出。

## 导入

选文件 → 解析 → 填进表单 → 提示"已导入，检查后点保存"。

**导入不自动保存。** 导入的配置可能来自另一台机器，目录未必存在；
直接落盘会把一个跑不起来的项目写进状态目录。检查和保存留给人。

## 历史筛选

输入框实时过滤，匹配范围是：出发阶段、到达阶段、门禁号、备注。
中文阶段名和英文代码都能匹配——历史里存的是 `IMPLEMENT`，
界面上显示的是"实现"，两边都要能搜到。

## 测试

这一轮没有新增自动化测试。导出是 `Blob` + `a.click()`，导入是
`file.text()`，两者都在浏览器里；现有测试环境没有 DOM。

**这是这一轮的真实缺口**：功能可用，但没有回归保护。
